# DOC_TEMPLATE.md — Master Doc Standard

Single source of truth for project documentation. **Edit here only.**
Copies in git repo roots are generated by SYNC.md and must not be hand-edited.

---

## 1. Every project doc gets a header block

Add this at the top of every doc/README/SPEC. Keeps a per-doc audit trail that survives even messy git history.

```
---
title: <doc name>
project: <repo name>
created: <YYYY-MM-DD>
---
```

## 2. Every doc ends with a footer (update on every change)

```
---
## Doc History
| Date       | Agent/Model           | Harness      | Change                     |
|------------|------------------------|--------------|----------------------------|
| 2026-09-15 | arcpy-agent / model-X  | openclaw     | Initial version            |
| <date>     | <agent / model>        | <harness>    | <what changed>             |
---
```

Rules:
- Append a row, never rewrite history.
- `Agent/Model` = which agent/model touched it. `Harness` = openclaw / manual / IDE.
- If you change the doc, add a row. No exceptions.

## 2b. Confirmation gate (coding agents)

- **Interactive session (live user):** don't change/commit anything until the user confirms the plan. Present the proposed change + commit message, then wait.
- **Subagent / autonomous run:** proceed once the task is explicit — the orchestrator's approval stands in for the user.
- Unsure which you're in? Ask for confirmation.

## 3. Commit convention (machine-readable trail)

Prefix commits that touch docs:

```
doc(<repo>): [<agent>/<model>] <short summary>
```

Example: `doc(subtitle-translator): [arcpy-agent/gemma] updated SPEC.md`

Full audit trail = `git log --grep="^doc("` — no extra tooling, works in any repo.

## 3b. General commit convention (all commits — perf tracking)

Every commit carries agent/harness/model so agent+model performance is traceable:

```
<type>(<repo>): [<agent>/<model>|<harness>] <short summary>
```

- `<type>` = `feat`/`fix`/`refactor`/`chore`/`doc`/`test`/`perf` (conventional-commits style).
- `[<agent>/<model>|<harness>]` = who made it, e.g. `[jainii/kimi-k2.7|openclaw]` or `[will|manual]`.
- `<harness>` = openclaw / manual / IDE.

Examples:
- `feat(subtitle-translator): [jainii/kimi-k2.7|openclaw] parallel proofread option`
- `fix(subtitle-translator): [jainii/deepseek-v4-flash|openclaw] srt offset bug`
- `chore(yt-transcriber): [will|manual] bump deps`

Why: attribute quality/speed to agent+model+harness via `git log --format` — no reliance on chat logs.
Doc commits still use `doc()` from §3 (same info, tagged as docs). List the actual model used for that change.

## 4. Version note

- Docs are living files; don't bump a semantic version on every edit.
- Only bump `title`'s version if the doc's scope/contract changes materially.
- History table is the change log — keep version numbers out of it.
